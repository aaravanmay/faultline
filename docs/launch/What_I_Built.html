01The problem (simply)

"AI agents" are programs that use AI to do a job on their own — a research assistant that searches the web and writes a report, or a coding assistant that edits your files for you. Companies are racing to put these everywhere.

Here's the scary part. When one of these agents is handed bad information — a stale price, half a file, an empty search — it usually doesn't crash and doesn't warn you. It just confidently does the wrong thing, and you'd never know:

The AI doesn't crash.
It lies.

It places the order on a wrong number. It writes a confident report with made-up facts. It deletes half your file. No error, every test passes green. Almost nobody is testing for this — and as these agents start handling money, code, and real decisions, it's exactly the failure that will bite.

02What I built

faultline deliberately breaks an AI agent's tools — feeds it wrong, stale, empty, or cut-off data on purpose — and catches the moment the agent silently does the wrong thing. Two pieces, both working today:

  • An engine (open-source, in Python) that injects these failures and detects when the agent quietly went wrong — without needing to know the "right answer."
  • A web dashboard (a full sign-in app + database) that shows a team how resilient their agent is over time and flags when a change makes it worse.

I designed and built all of it myself — the engine, the detection logic, the website, the dashboard, the database.

03The real results — the part that matters

Anyone can claim their tool works. So I used it — plus the "what does a silent failure look like" checklist it's built on — to hunt sixteen of the most popular open-source AI apps in the world. Every one had a hidden silent-failure flaw — 17 separate bugs in total (LlamaIndex had two). For each, I wrote the actual fix plus a test that fails before the fix and passes after. Two are already submitted as official pull requests on GitHub; the other fifteen are fully built and ready for me to submit. (To be precise: I found these by combining the tool with careful code review — and the tool now re-catches all 17 on its own in a live run, 15 of them with no API key needed. I write the fix and tell the tool the rule to check; the tool does the catching.)
